Благодаря этому GEMINI_API_KEY не включается в браузерную сборку и остаётся на стороне backend.

## AI и API

Для генерации рекомендаций используется Google Gemini API.

Основная модель задаётся через переменную окружения GEMINI_MODEL. Если она не указана, Worker использует модель, заданную в конфигурации приложения. Также предусмотрены резервные модели на случай ошибки основного запроса.

AI получает данные заполненной анкеты и формирует структурированный JSON-ответ.

Результат включает:

- общую стратегию поступления;
- персонализацию на основе данных анкеты;
- шесть университетов;
- две рекомендации категории ambitious;
- две рекомендации категории balanced;
- две рекомендации категории safer;
- анализ соответствия профилю;
- факторы, влияющие на поступление;
- рекомендации по extracurricular activities;
- roadmap;
- следующие действия;
- источники и disclaimer.

Roadmap состоит из пяти последовательных этапов: ближайшие действия, следующие месяцы, развитие профиля, подготовка заявки и этап подачи документов.

При включённом Google Search grounding модель может использовать поиск для проверки официальной информации. В качестве источников должны использоваться официальные страницы университетов или государственные ресурсы.

Если online-проверка недоступна, сервис переходит в model-only режим и не представляет неподтверждённые стоимость, acceptance rate, дедлайны и другие изменяемые данные как проверенные факты.

## Backend и безопасность

Cloudflare Worker выполняет несколько задач перед обращением к Gemini:

- проверяет origin запроса;
- применяет CORS;
- валидирует профиль пользователя;
- ограничивает размер входного запроса;
- применяет rate limit;
- кеширует одинаковые запросы;
- скрывает Gemini API key от frontend;
- проверяет структуру ответа модели;
- обрабатывает ошибки и fallback-модели.

Rate limit составляет до четырёх запросов в минуту на один IP.

Для кеширования профиль преобразуется в SHA-256 hash. Повторный запрос с тем же набором данных может быть получен из edge cache без повторной генерации результата.

В Gemini передаются данные анкеты, необходимые для построения рекомендаций. Имя и фамилия пользователя для генерации рекомендаций не требуются.

## Данные и источники

В проекте используются несколько типов данных:

- данные анкеты пользователя;
- TopoJSON World Atlas для отображения карты;
- координаты университетов для размещения маркеров;
- данные, полученные через Gemini;
- официальные страницы университетов и государственные источники при использовании Google Search grounding.

AI-рекомендации сами по себе не считаются официальным источником информации.

Стоимость обучения, дедлайны, визовые требования, требования конкретных программ, доступность Foundation и правила работы во время учёбы могут изменяться. Перед принятием решения пользователь должен проверить эти данные на официальном сайте университета или соответствующего государственного органа.

cd frontend

Для подключения production Worker необходимо создать frontend/.env.local:
VITE_ADMISSIONS_API_URL=https://hail-mary-admissions-api.hail-mary-admissions-api.workers.dev

## Запуск Worker

Перейдите в директорию API:

cd api
npm install
copy .dev.vars.example .dev.vars

В .dev.vars необходимо указать действующий:

GEMINI_API_KEY=...

После этого Worker запускается командой:

npm run dev

Для использования локального Worker необходимо изменить frontend/.env.local:

VITE_ADMISSIONS_API_URL=http://127.0.0.1:8787

## Ограничения

Hail Mary является инструментом для предварительного подбора и планирования поступления, а не официальной системой университета или приёмной комиссии.

Рекомендации зависят от полноты данных, которые пользователь указал в анкете.

Категории ambitious, balanced и safer показывают относительное соответствие профилю. Категория safer не означает гарантированное поступление.

Оценка admission chance является ориентировочной оценкой на основе доступного профиля и не является статистически рассчитанной вероятностью или гарантией поступления.

Acceptance rate университета также не равен индивидуальной вероятности поступления конкретного абитуриента.

Если Google Search grounding недоступен, результат работает в model-only режиме. В таком режиме изменяемые данные необходимо дополнительно проверять по официальным источникам.
